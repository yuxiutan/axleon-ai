# 資料模型與口徑

---

## 資料表

18 張表，以 Node 內建 `node:sqlite` 儲存於單一資料卷。

| 分組 | 資料表 | 內容 |
|---|---|---|
| 主檔 | `fleets`、`users`、`vehicles` | 車隊、帳號與角色、車輛主檔 |
| 行駛 | `trips`、`driver_tasks`、`live_state` | 行程與停靠點、任務派遣、即時狀態 |
| 風險 | `events`、`maintenance_alerts`、`work_orders` | 異常事件、維修預警、工單與核決紀錄 |
| 分析 | `attribution_vehicle`、`attribution_route`、`attribution_evidence`、`attribution_action`、`attribution_baseline` | 影響因子分析的車輛／路線維度、證據、建議動作與基線 |
| 說明 | `metric_docs` | 指標口徑說明，供畫面與 AI 共同引用 |
| AI | `ai_cache`、`ai_feedback` | 答案快取、使用者回饋 |
| 稽核 | `event_logs` | 操作與核決紀錄 |

每次寫入都更新資料版本，答案快取據此失效。

## 語意層：指標的唯一定義處

百公里油耗、時間加權怠速佔比、同車型中位數偏差、事件密度等指標只定義一次，畫面、報表與 AI 共用同一套口徑。

口徑若不統一，跨頁面與跨報表的數字就無法互相對照，也無法據以排出查核順序。

核心口徑：

```
百公里油耗 = Σ耗油量(L) ÷ Σ里程(km) × 100
```

此處為總量相除，不是各趟百公里油耗的算術平均。兩者在趟次長短不一時結果不同，系統一律採前者。

## 來源三級標籤

畫面上的每一個數字都帶著來源標籤，報表與 AI 輸出亦同：

| 標籤 | 意義 | 可變動 |
|---|---|---|
| **官方實算** | 直接由主辦方競賽資料集計算 | 否 |
| **情境估算** | 以官方樣本為基礎的推估，標明假設 | 否 |
| **Demo Mock** | 操作流程展示資料 | 是（可重置） |

三者在畫面與報表上分開標示，不混算成效。Reviewer 有一道專門的檢核防止模型把 Demo 數字說成官方實算。

## 官方樣本

來源為 2026 和泰 AI 黑客松主辦單位提供之競賽資料集。

### 行程識別

依主辦方《解題資料補充 FAQ》Q3，`journeyCode` 並非全資料集唯一，須與 `enabledCode` 併用才能唯一識別一趟行程。系統以此複合鍵切趟。

同份 FAQ Q1 說明 `fenceId` 全為空值，代表所有車輛皆未建立地理圍籬，因此系統不依賴圍籬類欄位。

### 清洗規則

```
單趟里程 ≥ 1 km
單趟耗油 > 0 L
百公里油耗介於 5 – 80
```

清洗後有效樣本為 20 台車、2,274 趟、52,009.7 km、13,293 L，涵蓋 27 個有效抽樣日。

抽樣日不連續，因此系統以營運日為單位推估，不直接年化。

### 分層驗證

| 層次 | 方法 | 結果 |
|---|---|---|
| ① 跨車輛 | 20 台車怠速佔比 × 百公里油耗 | r = **+0.842**（R² = 0.709） |
| ② 車型內 | 300 / 500 / 700 系分層 | 300 **+0.8929**（R² 0.7974, n=10）<br>500 **+0.6658**（0.4433, n=5）<br>700 **−0.4403**（0.1939, n=5） |
| ③ 車輛內對照 | 同一台車高怠速趟 vs 低怠速趟 | 多數車輛為正，仍受任務型態影響 |

分車型基準（油耗中位數，L per 100 km）：300 → 15.14、500 → 22.44、700 → 42.37。

怠速是值得優先查核的候選因子，但分車型後方向不一致（700 系為負相關），不足以作為因果或責任判定。跨車型的 +0.842 很可能受車型組成影響。

這是系統只輸出查核優先序、不輸出責任占比的直接原因，該限制同時寫進模型的系統指令與 Reviewer 檢核。

## 影響因子的處理方式

| 因子 | 狀態 | 依據 |
|---|---|---|
| 車型 | 必要控制變數 | 三車型加權油耗與怠速差異顯著，不得跨車型直接比較單車 |
| 怠速 | 待分層驗證 | 全體相關可能受車型組成影響，需查看各車型內相關與相近任務樣本 |
| 速度 | 候選共變量 | 目前只有平均速度，缺少路線壅塞與道路型態標籤 |
| 負載 | 候選共變量 | 目前只有平均負載，正式比較需配對任務與載重區間 |

## 資料限制與替代方案

| 限制 | 替代方案 |
|---|---|
| 無駕駛識別 | 以車輛自身歷史基線比較；試點時綁定班表 |
| 無保養紀錄 | 以里程與運轉時數推估 |
| 無貨單與 SLA | 由車隊自行維護參數表；未設定時顯示「未設定」，不推測違約後果 |
| 資料非連續 | 以營運日為單位推估，不直接年化 |
| 60 秒取樣 | 以分鐘級視窗設計，不做秒級判別 |

## 隱私

- 車輛與駕駛一律以代碼表示（如 A-018、D-127），不寫姓名
- 不談論或推測任何人的姓名、情緒、健康或私人狀況
- 不做駕駛之間的排名；駕駛只看得到自己的紀錄
- 送往模型的內容僅包含查詢後的統計結果與代碼，不含姓名、地址等個資
- 語音辨識在裝置端進行，錄音不離開手機
- 答案快取鍵含車隊與角色，跨車隊、跨角色不會取到彼此的答案
